# 判据清单（交付闸门）

发版前、写新功能前、以及 review 别人的产出时过一遍。**每条都对应 `LESSONS.md` 里至少一次真实事故**（方括号内为事故编号）。

**执行规则（主理人 Phase 6）**

1. 每条标 `PASS` / `FAIL` / `N/A`；`N/A` 必须写原因（环境不具备 / 不适用 / 已列欠账）。
2. 每个 `PASS` 要写**证据路径**：`文件:行号`、命令与原始输出，或 `E0–E4` 等级 + 取证方式。**没有证据的 PASS 视同 FAIL**。
3. 存在任一 `FAIL` → 不得交付，退回对应 Phase。
4. `N/A` 项汇总进 `LESSONS.md` §5 已知欠账表；已修复项从欠账表删掉。
5. 报告附**闸门结果表**与**证据等级分布**；禁止为了让闸门全绿把 FAIL 改成 N/A。
6. 清单没拦住的新失败 → 按 `../SKILL.md` §5 闭环回写：追加 `Lxx`、新增 `Cxx`、编号互指。

## D. 硬件与并发语义

- [ ] **C31** [L30] 出现毒值 / 魔数时，先查了**初始化顺序**，还是又打了一处补丁？组件 `init` 能否重复调用。
- [ ] **C32** [L31] 每个 ISR 是否清掉它负责的**全部**标志。
- [ ] **C33** [L07, L32, L36] 寄存器 / 外设能力是查过**当前型号**手册，还是从别的系列记忆套过来的？无 FPU、不支持非对齐访问、禁堆分配与动态分发是否落实。
- [ ] **C34** [L33] 同名不同物的算法 / 协议（CRC 变体等）是否写全名与参数？引脚名、总线名、器件型号是否逐字一致、未做大小写归一化。
- [ ] **C35** [L34] vendor 源码是否保持只读？改动是否会在下次生成时被覆盖。
- [ ] **C36** [L35] 分层预算（喂狗窗口 / 任务周期 / 串口行宽）是否**放在一起比过大小**？改动任一层是否重算另两层。

## E. 验证类假象：逐条反问

- [ ] **C45** [L45] 串口有输出 ≠ 调度正确：是否附了启动序列原文与各任务心跳？
- [ ] **C46** [L46] OTA 返回 success ≠ 双槽生效：是否复位后回读 `fw_version` 与 TAMP 备份寄存器？
